# Schema Migrations

Rules (conventions §2): every schema carries `"x-version"`. Any field change (add,
remove, rename, retype, semantic change) bumps that schema's version and adds an entry
here. Binary format changes additionally bump the IAP magic/version in
`schemas/FORMAT.md`. Golden vectors are regenerated by the Python reference and
re-validated by every language before a migration is merged.

Entry format: `## <date> — <schema> v<old> -> v<new>` + what changed, why, migration
path for stored data.

## 2026-08-29 — generator redesign (shared efficient price) + book semantics fixes; golden vectors regenerated

Deliberate, versioned regeneration of the data-dependent goldens. No wire-schema
field changed (`market_event` stays v1; IAP1 magic/version unchanged) — what
changed is pinned SEMANTICS plus the pinned synthetic vectors themselves:

- **Generator (research-validity fix, CRITICAL)**: equity venues previously
  diffused independent mids per (instrument, venue), leaving the consolidated
  equity book crossed ~95% of the time. Redesigned: ONE shared regime-switching
  efficient price per INSTRUMENT (1s grid, dedicated per-instrument SplitMix64
  stream) with per-venue bounded AR(1) microstructure noise, venue latency on
  receive_ts, and per-slot repricing cancels of quotes the efficient price moved
  through. Measured consolidated crossed-book fraction on equities: **0.80%** of
  event states (target < 2%). `configs/marketdata/generator.json` equities keys changed:
  `vol_regimes` is now `{sigma_ticks_per_s, switch_prob_per_s}` and `venue_noise`
  `{rho, sigma_ticks, max_ticks}` was added. Determinism unchanged (same seed =>
  byte-identical files; verified).
- **Book semantics (conventions §4, pinned)**: (a) side-domain rule — events with
  side > 1 on side-indexed types (ADD/QUOTE/SNAPSHOT/TRADE) are dropped + counted
  (`invalid_side_dropped`), never raised; (b) broken-burst rule — a sequence gap
  inside an active SNAPSHOT burst marks it broken; the burst's last record no
  longer clears `stale`, only a later complete gap-free burst does (FORMAT.md §4
  updated); (c) EXECUTE wording corrected: it fills the REFERENCED order (valid
  feeds reference the FIFO head); (d) checkpoints now carry `arrival_order`,
  `snapshot_broken` and the `invalid_side_dropped` counter so restore round-trips
  the global resting-order arrival order exactly.
- **Regenerated goldens** (Python reference, brute-force cross-validated before
  writing): `events_eq_mbo.jsonl`, `events_fx_quote.jsonl`,
  `expected_book_states.json`, `expected_codec_sha256.json`, `splitmix64.json`,
  `expected_features.json`, `expected_alpha.json`, `expected_backtest.json`;
  `configs/strategies/alpha_params.json` refitted on the regenerated data.
  `expected_replay_fills.json` was DELETED — the C++ reference regenerates it
  from the new vectors. `expected_tca.json`, `expected_portfolio.json`,
  `expected_risk_decisions.json` embed pinned synthetic inputs and are unchanged.
- Migration path: every other language must re-run its golden suite against the
  regenerated vectors and mirror the two new book rules and checkpoint fields.

## 2026-09-06 — IAP1 v1 -> v2 (integrity trailer), book/engine checkpoints v2, anomaly goldens; codec SHA goldens regenerated

No `market_event` field changed (`market_event.schema.json` stays v1; the schema's
`order_id` / `price_ticks` descriptions now state the pinned rules). What changed:

- **IAP1 version 2** (`schemas/FORMAT.md` §2): every encoder now writes `version = 2` and a
  16-byte trailer `crc32 | reserved 0 | count echo` (CRC-32/zlib over header + records).
  Decoders verify it (CRC, count echo, reserved) and still read version-1 files as unverified
  legacy input. The 72-byte record layout is untouched. `expected_codec_sha256.json` was
  regenerated (the trailer changes the bytes); the golden JSONL vectors are byte-identical.
  Migration: existing `*.iap1` files keep loading (v1); re-encode to get integrity checks.
- **Book semantics (conventions §4 / API_CORE §4, pinned)**: (a) QUOTE/SNAPSHOT with
  `order_id = 0` are first-class — the book assigns synthetic ids in the reserved range
  `>= 0xFFFF000000000000` (`side<<40 | ordinal`); QUOTE clears the side by walking its levels; an
  explicit QUOTE id resting on the other side, a repeated SNAPSHOT id inside a burst, and a
  duplicate ADD id are dropped + counted (`unknown_order_events`); (b) SNAPSHOT countdown
  validation (`snapshot_restarts`; skipped records break the burst); (c) matching gated on
  `status == TRADING` — crossing ADDs rest during HALT/AUCTION/CLOSE; (d) payload-domain and
  i64-overflow drops (`invalid_payload_dropped`), unknown event_type drops
  (`unknown_type_dropped`, previously raised), MODIFY price mismatch drops
  (`modify_price_mismatch`); (e) sequencing: first sequence accepted whatever its value (0
  legal), in-stream sequence reset via a SNAPSHOT burst restarting below `last_sequence`
  (`sequence_resets`, `sequence_epoch`) and `reset_sequence()`; optional hold-back buffer
  `reorder_window` (0..4096) with `late_recovered`; (f) ConsolidatedBook merges non-stale
  venues only and exposes `is_crossed/is_locked/active_venues/stale_venues`; consolidated
  `trade_flow` saturates. Clean goldens (`expected_book_states.json`) are unchanged by
  construction (clean vectors never exercise these paths) and were re-validated.
- **Checkpoints x-version 2** (API_CORE §4-§5): book checkpoints add `x-version`,
  `has_sequence`, `sequence_epoch`, `snapshot_countdown`, `snapshot_synthetic_next`,
  `reorder_window`, `reorder_pending` and six new counters; engine checkpoints add
  `x-version`, `keep_checkpoints` (now carried by every port), `keep_snapshots`,
  `snapshots_emitted`, `reorder_window`, `universe`, `unknown_instrument_dropped`,
  `unknown_venue_dropped`. Version-1 checkpoints are rejected (`x-version` mismatch). C++ gained
  a JSON checkpoint codec; the format is cross-language (golden
  `expected_checkpoint_eq_1000.json`).
- **New goldens**: `events_eq_anomalies.jsonl`, `events_fx_anomalies.jsonl`,
  `expected_anomaly_states.json` (generated by `python/tools/make_golden_anomalies.py`,
  cross-validated against the extended brute-force book), `expected_checkpoint_eq_1000.json`,
  `jsonl_reject_cases.txt`.
- **Normaliser QC report v2**: per-stream counters add `sequence_resets` and
  `ts_regression_dropped`; duplicate detection is windowed (65,536 sequences per stream);
  in-stream `exchange_ts` regressions are dropped + counted instead of being re-sorted; venue
  sequence resets are kept as new epochs instead of being discarded as duplicates. The pinned
  dataset (`data/`) is unchanged in content (verified: identical normalized JSONL; IAP1 files
  gain the v2 trailer on regeneration).
- **Reference data** (`configs/instruments/instruments.json`): sessions gained `timezone` (IANA; `UTC` for
  the synthetic venues — UTC bounds unchanged) and the file gained `fx_week`; loading validates
  fail-fast. Generator config gained `equities.halt.reopen_auction` (default false — dataset
  unchanged) and `reopen_call_s`.
- Migration path: every port re-runs its golden suite; adapters writing IAP1 get the trailer
  for free; any code that read the book counters must add the six new ones.

## 2026-09-06 — round-3 RESEARCH: feature ingestion, labels, alpha provenance

Feature/label/alpha semantics changed; every golden the research layer owns was
regenerated and every port updated. Nothing here is backwards compatible with a
stored feature parquet or an `alpha_params.json` written before this entry.

- **`OrderBook.apply` / `ConsolidatedBook.apply` return `ApplyStatus`**
  (APPLIED / DROPPED / HELD) in all four languages. Additive for callers that
  ignore the value; the feature engines now REQUIRE it (API_FEATURES §2).
- **Feature engine (all four ports)**: only APPLIED events feed rolling state;
  an `exchange_ts` regression is dropped + counted before the book sees it; a
  change to the stale-venue SET triggers a view-only *staleness refresh*; a
  stale→fresh recovery CLEARS all rolling state and re-anchors warmup
  (`warmup_after_recovery`); mid samples compare against the last RECORDED mid;
  ratios with an unreliable denominator are INVALID (the guard is an exact
  integer sample-count / integer-sum test, never a float `> 0`); quantities
  above `FEATURE_MAX_QTY = 2^40` are not folded into any window and an
  oversized merged depth makes the view unusable. Java additionally builds the
  merged view from a per-venue depth cache like the other ports.
- **Session time zones**: `configs/instruments/instruments.json` sessions MUST declare an
  IANA `timezone`; time-of-day features and 5-minute profile buckets are
  session-local. A missing timezone or a non-positive `tick_size` fails at
  start-up.
- **Labels (`data/features/*.parquet`)**: one mid sample per book REFRESH with
  a `tradable` flag; a label is valid only with a tradable anchor, a tradable
  AND fresh forward mid (`max(5 s, 2 x median quote gap)`) and no blackout
  sample inside `(t, t+h]`. New per-horizon column **`label_reason_<h>`**
  (uint8 bitmask, `iap.labels.LabelReason`). `features_summary.json` gains
  `crossed_frac`, gap statistics, `label_max_age_ns`,
  `label_valid_frac_by_horizon`, `label_zero_frac_by_horizon` and the
  invalid-label reason counts. **Re-run the feature pipeline** — an older
  parquet lacks `label_reason_*` and carries labels that span halts and gaps.
- **`tests/golden/expected_features.json`** regenerated;
  **`tests/golden/expected_features_anomalies.json` is new** (native-45
  sub-vector plus the ingestion counters on the anomaly vectors; all four
  languages reproduce it).
- **`configs/strategies/alpha_params.json` x-version 1 -> 2**: provenance header
  (`feature_version`, `data_version`, `git_commit`, `git_dirty`,
  `train_window`) and per-alpha `train_window` / `dead`. Every loader rejects a
  mismatched `feature_version`, an edited `z_clip`/`conf_scale`, a non-finite
  parameter and `sigma <= 0` with `beta != 0`. A dead alpha scores (0, 0).
- **FX05** scores only identified pairs (a currency must appear in >= 2
  observable pairs): AUD/USD, USD/CAD, USD/CHF, USD/JPY and NZD/USD now score
  NaN instead of a constant. `expected_alpha.json` regenerated.
- **`tests/golden/expected_adaptive.json`**: new `rolling_ic` section (mid
  series + signals + pinned ICs); `lifecycle` gains `ic_informative`.
  IC baselines (`research/baselines/run_*_ic.json`) carry
  `"baseline_kind": "oos"` and loaders reject anything else.
- **`research/baselines/*.json` x-version 1 -> 2** (API_ADAPTIVE §1): every
  baseline — distribution and IC alike — records the `feature_version` (the
  feature-registry hash) it was captured against, and every loader
  (Python `DriftBaseline.load` / `ICBaseline.load`, Java
  `BaselineLoader.requireFeatureVersion`) rejects a baseline from a different
  registry, or one carrying no `feature_version` at all. A baseline captured
  under another registry describes a feature whose semantics may have moved
  under the same name, so PSI/IC against it is meaningless. All baselines were
  regenerated; `signal_eq01.json` and the `signal_eq01` section of
  `expected_adaptive.json` gained the field with no numeric change. Stale
  baselines for alphas outside the current study subset (`run_eq09_*`) and a
  superseded pre-round-3 `run_fx10_ic.json` were removed rather than migrated.
- **`research/experiments.json` was reset**: experiments are now de-duplicated
  by (alpha, kind, canonical config) and one adaptive deployment counts as ONE
  experiment (it counted 211 monitoring evaluations). The old total (19 347)
  was an artefact of how often the scripts had been run.
- **Research backtester**: `BacktestConfig` gains `latency_ns` (time mode),
  `max_decision_age_ns`, `flatten_at_session_end` and `session_gap_ns`; Sharpe
  bars are zero-filled inside a session. `expected_backtest.json` stays the
  rows-mode regression.
- **Walk-forward** folds are quantiles of the ROW INDEX; degenerate folds are
  reported and count as failures; PROMOTE needs >= 3 non-degenerate folds and
  reads the UNCROSSED IC. All research reports regenerated; papers 01-04 carry
  dated errata.
- Migration path: regenerate `data/features` (`python3 -m iap.features`), then
  `research/alpha_reports/run_all.py` (rewrites `alpha_params.json`), then the
  goldens under `python/tools/`, then `run_adaptive.py` / `run_ml.py`.
