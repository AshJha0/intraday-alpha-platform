# Archived: the Java engine (frozen at v1.14.0, not built, not a port target)

This directory is the Java port of the platform (`com.iap.*`: codec, order
book, replay, features, alpha, risk, execution / SOR, contracts / trace,
lifecycle, portfolio, TCA, backtest, adaptive monitors, and the paper-trading
platform vertical with its `/metrics` server). It was FROZEN by
[docs/POLYGLOT.md](../../docs/POLYGLOT.md), archived in v1.15 (plan item
G-P1-3, owner-approved) and **retired from the release in v1.17** (WS-F item
F9, owner decision 2026-10-15; `docs/release/DECISION_N7_JAVA_IMAGE.md`,
closed).

**State: tag `v1.14.0` (commit `e15abab`), read-only.** At that tag CI ran
the full JUnit4 suite green: 575 tests, of which the seventeen `*GoldenTest`
classes are 124 golden-group tests, byte-identical to the Python reference
goldens in `tests/golden/`.

What "archived, retired" means, in full:

- **Not built.** No CI job, no release workflow and no image builds or tests
  this code. The `java` image (`deployment/docker/Dockerfile.java`) was
  removed from `.github/workflows/release.yml`, the CI `images` job and the
  release manifest in v1.17; the Dockerfile is kept beside this README
  (`Dockerfile.java`) as a record and is not referenced by anything.
- **Not a port target.** Parity policy (owner, 2026-10-15): Python is the
  reference for everything; C++ ports the execution, SOR and dark-venue
  rules (v1.17 F7); Rust ports only what Rust owns, the pre-trade risk
  controls and the venue simulator (F8). Nothing new is ported to Java, and
  the three-language parity table (python / cpp / rust) is the whole
  parity claim. The Java FROZEN paths left
  `tests/harness/polyglot_policy.json` in v1.15; goldens move on without
  this code, so after v1.14.0 it is not guaranteed to match `tests/golden/`.
- **One exception, deliberately kept: the Java risk engine
  (`src/main/java/com/iap/risk/`) remains the byte-identical mirror of the
  Rust risk engine.** The three risk goldens (`tests/golden/expected_risk_*.json`,
  generated by `rust/risk/src/bin/make_risk_golden.rs`) pin the Rust engine,
  the Python engine (`iap.risk`) and this mirror to the same decision and
  reason bytes. When F8 adds a pre-trade control to the Rust engine and
  regenerates those goldens, the Python engine is mirrored and this Java
  mirror is updated **only** because the Rust–Java pair must stay
  byte-identical (`PLATFORM_CONVENTIONS.md` §11.1). That is the only edit
  this directory accepts. It is proven by a reviewer replaying the goldens
  with a local JDK (`bash build.sh && bash test.sh`, JUnit4 jar at
  `/usr/share/java`); CI does not run it.
- **Deployment.** The Java `/metrics` container, its session-state exporter,
  the kill-switch admin API, the `java-platform` compose services and k8s
  Deployment, the `iap-java-state` claims and the operator network-policy
  rule are gone. The Python process `python -m iap.metrics serve`
  (`python/src/iap/metrics/`) serves `/metrics`, `/health`, `/ready` and
  `/status` in their place (compose `platform-metrics`, k8s
  `deployment/k8s/platform-metrics.yaml`); the admin API has no Python
  replacement — the manual halt is the config path
  (`docs/runbooks/RUNBOOK_incident_kill_switch.md`).

## How to restore (for the record)

The sources build in place (`bash archive/java/build.sh`), but the tests,
`demo.sh` and `paper.sh` use repo-relative paths (`../tests/golden`,
`../configs`) that assume the original location. To bring the engine back:

```bash
git mv archive/java java
# then revert the v1.15 G-P1-3 change set (see CHANGELOG.md, v1.15.0):
#   the `java` job in .github/workflows/ci.yml (and its entry in images.needs),
#   setup-java + junit4 in the `golden` job,
#   run_java / JAVA_GOLDEN_CLASSES in tests/harness/run_all.sh,
#   the Java engine in python/tools/risk_fuzz_nightly.py and risk-fuzz.yml,
#   java-kotlin in codeql.yml, the Java FROZEN entries in polyglot_policy.json,
#   the java row of the README parity table and the four-language counts;
# and the v1.17 F9 change set (CHANGELOG.md, v1.17.0): the `java` image in
#   release.yml and the CI images job, Dockerfile.java back under
#   deployment/docker/, the java-platform compose services and k8s manifests.
cd java && bash build.sh && bash test.sh   # JUnit4 jars at /usr/share/java
```

Then re-add `java` to the `protect-main` required status checks
(docs/governance/REPO_SETTINGS.md). The simplest exact restore is
`git checkout v1.14.0 -- java`.
