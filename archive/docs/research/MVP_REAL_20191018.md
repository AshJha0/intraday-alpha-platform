# MVP on a full real day — 2019-10-18 (v1.15)

The full MVP loop (market data → features → alpha → pre-trade risk → OMS / algos / SOR →
execution simulator → fills, costs, store) on one complete real ITCH session, with the v2
pre-registration realism config.

- **Command:** `python -m iap.mvp.real --dataset data/real/r7_20191018 --date 2019-10-18
  --symbols AAPL,MSFT,QQQ --config configs/prereg/v2.json --out data/real/mvp_real_20191018`
- **Data:** `r7_20191018` — an R7 *in-sample* day, ingested with current code (not a legacy
  dataset); not a holdout session.
- **Code:** main @ b0c7a2c (includes #115: kill switch cancels resting orders, fee double-count
  guard, fee schedule in the run identity, impact model in the manifest).
- **Run:** 2026-10-12 21:09 → 23:38 local, exit 0; ~6.0 M events in 2 h 29 m (~670 events/s);
  peak memory ~2 GB.

## Reading

1. **The alphas earn before costs on every symbol** (+$801 gross) — consistent with R7
   (EQ10, EQ05 passed the v1.15 R7 gate; re-issued 2026-10-24 as `ineligible`, evidence
   class **data-ineligible** under v2.0; this in-sample day is **exploratory**).
2. **Costs exceed the gross P&L ~12x.** The driver is turnover: ~22–26 k parent orders per
   symbol per day, i.e. a decision almost every second. Fees alone ($3.6 k) are 4.5x the gross
   edge. This is the end-to-end, in-dollars form of R7's "predictive, not yet tradable".
3. **The cost model is the current, known-optimistic one** (impact per child order, zero
   real-data venue latency, assumed fee tier — v1.15 review). Realistic costs would widen the gap.
4. **Not statistical evidence:** one in-sample day. It is an integration test and a cost baseline.

## Caveats

- **No end-of-day flatten.** The MVP loop has no flatten leg (`iap/mvp/real.py`: the prereg's
  `flatten_route` applies to the quoting backtest only), so the session ends with open positions
  (+132 AAPL, +148 MSFT, −292 QQQ shares). Net P&L marks them to market at the close; no closing
  trades are charged. Small relative to ~70 k parents; it does not change the conclusion.
- Each symbol's stream is read three times (count, hash, run) — a v1.16 performance item.
