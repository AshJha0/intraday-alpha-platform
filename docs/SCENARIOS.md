# Real-life scenarios — pinned behaviour and where it is tested

Every row names a scenario a production system meets, the real-world example,
the platform's pinned behaviour (the contract clause that governs it), and the
tests that construct the exact event sequence in each language. Scenario tests
are named after the scenario; cross-language determinism is additionally pinned
by golden vectors in `tests/golden/` consumed by all four suites
(`tests/harness/run_golden.sh`).

## CORE — events / codec / order book / replay / reference data

Documented gaps (not modelled, by design): negative prices (validator rejects
`price_ticks <= 0`; a price-offset convention in reference data is the
extension point), lot-size multiples (not enforced), iceberg/hidden liquidity
(representable as TRADE without book change, not generated), self-match at
the book level (risk-layer concern), and corporate actions (synthetic
universe).
