# Operator runbook, v2.0 (stage 11)

For the person who runs the platform day to day: what runs by itself, what you start, what each
failure means and who may change what. Everything here is a command that exists on `main`; where a
piece is still in another pull request it says so. The programme's evidence vocabulary (U0 section
10) is used throughout and nothing here upgrades a result's class:

> **independently confirmed** (a registered single-shot decision executed under custody separate
> from the developer) · **mechanically isolated** (the same, executed by the registered runner CR1
> under the developer's sole custody) · **development-supported** · **exploratory** · **rejected** ·
> **data-ineligible** · **pending**.

As of 2026-10-25 no result on `main` is above *development-supported*: no registered run has been
executed by CR1, and no independent party has reproduced anything
([REVIEW_PACK.md](REVIEW_PACK.md) section 0, [SHOWCASE.md](SHOWCASE.md)).

## 2. What runs by itself

**On every pull request and push to `main`** (`.github/workflows/ci.yml`): 17 required contexts
(the matrix with the risk each covers: [governance/REPO_SETTINGS.md](governance/REPO_SETTINGS.md)
section 1). The `lint-and-secrets` job (gitleaks, ruff, import-linter) is blocking; `advisory` is a
transitional alias for the ruleset's context name. `images` runs on `main` and on PRs that change
image inputs; `coverage` reports the whole-suite floor.

**Weekly, Mondays 04:17 UTC** (`.github/workflows/weekly-structural.yml`, also `gh workflow run
weekly-structural.yml`): the full C++ build with benchmark guards and coverage, the C++ sanitizer
run, and the whole Rust workspace (tests, clippy, benches, `rust/risk` coverage). A failure there is
a defect in a frozen copy or a timing regression: record it in
`docs/review/DEFECT_REGISTER_v1.19.md`; a fix to a frozen path needs a `POLYGLOT-OVERRIDE:` line
([POLYGLOT.md](POLYGLOT.md)).

**Nightly** (`risk-fuzz.yml`): fresh differential fuzz of the Rust and Python risk engines; a
divergence uploads the minimised script and fails. **CodeQL** on its own schedule. **repro-image.yml**
rebuilds the pinned reproduction image only when its inputs hash changes and commits the digest
(a bot commit; if the PR's checks then sit in `action_required`, push an empty commit from a human
account).

## 3. When a check fails

| failing check | first look | usual cause | who fixes |
|---|---|---|---|
| `python`, `python-312`, `python-slow` | the pytest tail in the job log | a semantics change without its golden; a platform-specific hash (pin per platform, as stage 7-8 did) | the author |
| `golden` | `tests/harness/run_all.sh --golden-only` locally | a Python change not ported to C++ / Rust, or a golden regenerated on the wrong platform | the author; goldens are regenerated by the `regenerate` dispatch, never by hand |
| `cpp`, `rust`, `rust-pyo3` | ctest / cargo output | a port out of step with Python | the author (C++ is parity-only, D5(a); Rust `risk` is normative, see PLATFORM_CONVENTIONS section 11.1) |
| `lint-and-secrets` (and so `advisory`) | which step: gitleaks, ruff, import-linter | a secret-shaped string (rotate it, it is in history), formatting, or an import that breaks a layer contract | the author; an architecture contract is changed only with a CHANGELOG line and the cycle list in `tests/architecture/test_layering.py` |
| `deployment` | `check_deployment.py --verbose`, `check_headline_numbers.py` | a FROZEN path changed without `POLYGLOT-OVERRIDE:`; a README number no longer matches its artefact | the author |
| `governance` | which step | an unsigned registry; a prereg citing a dataset the manifest lacks; a ledger that shrank; the live ruleset drifted from `repo_settings_live.json` (a warning) | the author; the ruleset drift is the owner's |
| `docs` | the check_docs tail | a dead relative link; an `iap.*` name that no longer imports; a status phrase older than the last tag (`--strict`) | the author |
| `supply-chain` | pip-audit / cargo audit / trivy output | a new advisory | bump the dependency, or a time-boxed entry in `.github/audit-ignores.json` with reason and expiry |
| `agent-evals` | the harness summary | a scored task regressed against `research/agents/eval_baseline.json` | the author |
| `reproducible-build` | the two wheel hashes | a non-deterministic build input | the author |

Known flake, now pinned: `test_maker_real_parallel.py` clamped its process pool to the RAM free on a
loaded runner; the test pins the probe since stage 11 (S5).

## 4. Research: families and the loop (stage 7-8)

The family specifications, the research loop (`iap.research.loop`, `tools/research/run_family.py`)
and the ML protocol are in the stage 7-8 pull request, not on `main` as of this runbook. When it
lands: `PYTHONPATH=python/src python tools/research/run_family.py <family> <partition>` runs one
family on one partition and exits 2 on a refusal (unregistered real data, `fit_allowed: false`, a
partition the loop may not read). The memory-budget test
`python/tests/architecture/test_research_loop_memory.py` fails when the loop's peak RSS on the
synthetic fixture exceeds its declared budget; raise the budget only with the measurement in the
CHANGELOG. Every real-data read goes through `iap.io` and the guard hook of `iap.core.guard`
([governance/DATA_ACCESS_PATHS.md](governance/DATA_ACCESS_PATHS.md)); a reader anywhere else fails
the AST test `test_guard_hook.py`.

## 5. A registered run (CR1)

Preconditions, all verifiable without reading sealed data:

1. A signed prereg with a `registered_run` block (`partition`, `dataset_hash_id`, `image_digest`,
   `command`): `PYTHONPATH=python/src python tools/verify_signatures.py --trust-ref origin/main --strict`.
2. `deployment/docker/IMAGE_DIGEST` equals the bound digest ([REPRODUCTION.md](REPRODUCTION.md) section 4).
3. The dataset id is in `research/data_manifest.json` (`python tools/data_manifest.py check`).
4. The three sealed services are up as their identities (section 6) and the runner answers
   `python tools/runner/run.py whoami` with `iap-runner`.
5. The repository settings of REPO_SETTINGS.md section 7 are set (as of 2026-10-25 they are **not**:
   no `sealed` environment, no `results` branch; the run is refused at the environment step).

Then: Actions tab > `registered-run` > run with the prereg path; approve the `sealed` environment
when prompted (the owner, not the runner). The job verifies registration -> digest -> identity ->
dataset, executes once, pushes one commit to `results` and uploads the redacted log. Read the result
on the `results` branch (`results/<slug>/<seq>/{result.json,hashes.json}`) and verify:
`python tools/runner/run.py verify --prereg <path> --commit <sha> --seq <n>` and
`python tools/sealed_service.py verify-checkpoints research/audit/CHECKPOINTS.jsonl`. Its class is
*mechanically isolated* while the developer holds custody of the machine (property 6 of the threat
model); nothing in the tooling makes it *independently confirmed*. A refused run is recorded, never
retried without a new registration ([governance/RUNNER_THREAT_MODEL.md](governance/RUNNER_THREAT_MODEL.md)).

## 6. The sealed services (Windows workstation, owner)

Install once per partition as [governance/SEALED_DATA.md](governance/SEALED_DATA.md) section 5. Day to day:

```bash
python tools/sealed_service.py serve --partition b --root C:\iap-sealed\b        # as iap-sealed-b, one per partition
python tools/sealed_service.py verify --root C:\iap-sealed\b                     # audit chain and ledger (sealed identity)
python tools/admin/isolation_probe.py                                             # 5 operations x 4 partitions, outcomes only
```

The development identity must be DENIED on every partition (observed 2026-10-25); the other identities
are exercised only with `IAP_ISOLATION_CREDENTIALS` set (defect D-46). Never copy a sealed file out
of its partition; a `checkpoint_pending.json` blocks further reads until `publish`.

## 7. Reproduce a committed result

```bash
bash tools/repro/reproduce.sh                      # the pinned image by digest; B8 v2 and the REL-08 scorecard, byte for byte
python tools/repro/compare_reproduction.py --out repro_out ...   # exit 0 = reproduced (REPRODUCTION.md section 3 has the full line)
```

The status this gives is "reproduced in the pinned image by CI", not "reproduced independently"
(REPRODUCTION.md section 5). Result files over 1 MB are release assets, not tree files:
`python tools/result_artefacts.py list | check | fetch <path>` (manifest
`research/v118/RESULT_ARTEFACTS.json`; a hash mismatch is a refusal).

## 8. Signatures, trust roots, settings

```bash
PYTHONPATH=python/src python tools/verify_signatures.py --trust-ref origin/main --strict   # every signed document
PYTHONPATH=python/src python -m iap.agents.cli verify-board --trust-ref origin/main        # blackboard chain and keys
python tools/data_manifest.py check                                                        # preregs cite manifest datasets only
python tools/repo_settings_snapshot.py check                                               # live ruleset vs the committed snapshot (gh)
```

A signature proves the document did not change after signing, and nothing else
([governance/TRUST_ROOTS.md](governance/TRUST_ROOTS.md), "What a signature proves"). Re-signing
after a registry change and key rotation: TRUST_ROOTS.md. The private key never enters the
repository, a log or a chat.

## 9. Owner-only actions (none applied by any file)

Repository settings: REPO_SETTINGS.md sections 1 (the required-check matrix and the `advisory` to

Naming the independent party for P2 (REPRODUCTION.md section 6). Purchases, signatures and sealed
