# v1.17.0 release notes (2026-10-16)

## Theme: execution quality and breadth

v1.16 showed that neither taking nor making pays on these alphas. v1.17 therefore
worked on the two things that could still change that: how well an order is
executed, and how many independent bets a book can hold. It also added a real
second venue, tightened the statistics, and brought the new execution rules to
C++ and Rust.

**The headline results are negative, and they are stated as such:**

- The pre-registered net-of-cost screen (C6) passes **0 of 22** candidates on
  multi7 (1 not screened; `research/breadth/screen/SCREEN_multi7.md`). Gross
  edges exist, but the round-trip cost is larger than each of them.
- So the breadth book (C8) was registered by the owner under option (a): the
  screen is a hard gate, the confirmatory run refuses every candidate, and **no
  confirmatory look is made**. The holdout stays unread
  (`research/preregs/breadth_book_prereg.json`, signed by the owner).
- B7 (fresh test of signal-aware execution) and B8 (two-venue router on real
  Nasdaq + IEX books) ship as tested code with documented run commands. Their
  real-data results need the IEX overlap days, which are being ingested now;
  they land in **v1.17.1**.

## What shipped

### Data (WS-A)
- **A1 IEX HIST codec** (`iap.marketdata.iex`): IEX's free daily pcap / pcapng
  captures, TOPS / DEEP / DEEP+, translated into the platform's event stream,
  with TOPS as an oracle for the rebuilt book.
- **A2 / A2b process-and-delete** (`python -m iap.marketdata process-day`): one
  approved download, ingest, features, keep list, delete; slim layout for wide
  datasets.
- **A3 breadth universe**: a rule fixed before any breadth statistic, measured
  on 2019-01-30 (100 names, 29 of them ETFs; `research/breadth/universe.json`).
- **A4 IEX overlap set** (`process-iex-day`): the nine Nasdaq / IEX overlap days.
  The TOPS oracle quotes the **cumulative** round lot (the first price where the
  displayed size from the top reaches a round lot): it matched all 113,807 TOPS
  quotes in the first 15 M DEEP+ messages of 2025-11-28. Normalized events are
  kept for these days so B8 can replay both venues. Day results: v1.17.1.
- **A5**: share-normalised `_v2` features, per-session ADV in the simulator,
  `TRADE_BUST` end to end.

### Execution quality (WS-B)
- **B1 implementation-shortfall benchmark**
  (`python -m iap.research.execution_benchmark`). The depth-50 re-run on multi7
  shows that at 0.5 % ADV the old 10-level walk cap, not the book, caused the
  "depth exhausted" readings; at 2 % ADV the displayed book itself runs out
  (`research/execution/benchmark/DEPTH_COMPARISON_multi7.md`).
- **B2 / B3** signal-aware urgency and pacing; **B4** quote fading; **B5**
  queue-aware cancels with the execution / cancel depletion split; **B6** markout
  decomposition by fill type and regime with day-clustered standard errors.
- **B8** two-venue router on real books: merged stream, per-venue fill
  probability and toxicity, paired router-vs-pinned evaluation (results: v1.17.1).
- **B9** rule-4 queue parity in the Rust venue simulator.
- **B10** dark / midpoint venue: **modelled, not measured** (no free dark-pool
  data exists), fitted on Nasdaq hidden prints, with dark-first routing.
- All opt-in; every registered result and golden is unchanged with the options
  off.

### Breadth and signals (WS-C, WS-D)
- **C1 / C2 / C7** cross-sectional book through the optimiser and the breadth
  report. **C3** `linear_z_v2`, **C4** 15 m – 1 h horizons, **C5** regime model
  and regime gate. **C6** net-of-cost screen. **C8** registered (above).
- **D1** GBM alpha model, **D2** meta-labelling with a calibrate / select split,
  **D3** conformal sizing, **D4** clustered zoo gate and demeaned CPCV path IC.
- **Statistics revision v1.17** (WS0): one gate statistic everywhere, the R7
  deflated Sharpe recomputed at the registered N, ML looks in the multiple-
  testing ledger.

### Agents (WS-E)
- **E1** spend ledger and caps; **E2** research assistant (Sonnet 5.5), **E3**
  morning ops agent and **E4** docs-sync agent (Haiku 5.5), on one budgeted,
  ledgered tool loop. The LLM never computes a number or signs anything.

### Engineering (WS-F)
- **F1** reproducible build, SBOMs, coverage floor, link check; **F3** mypy over
  agents / llm / mvp / paper; **F2 / F9** Java retired from the release and image
  digests pinned.
- **F4 / F5** a committed real ITCH slice (AAPL, 2019-01-30), C++ tick-to-trade on
  real depth (p50 1,535 ns, p99 2,943 ns; `benchmarks/results_tick_to_trade.md`),
  MVP latency and peak-RSS guards, a faster replay hot path with outputs
  unchanged.
- **F7** hand-written C++ parity ports of the new execution rules, including the
  B10 dark venue (part 2), each with a byte-for-byte golden from the Python
  reference. **F8** the dark-first pre-trade controls in the Rust risk engine,
  mirrored in Python.
- **Determinism fix**: the fill-hazard model is evaluated with scalar maths in a
  fixed order (the C++ order), so its last digit no longer depends on the CI
  runner's CPU.

### Docs (WS-G)
- **G1** showcase; **G2** EXECUTION_QUALITY, PORTFOLIO_BREADTH, SIGNAL_RESEARCH,
  DATA_SOURCES; **G3** COOKBOOK and LEARN at 140 each; **G4** PowerShell-safe
  runbooks. The post-release truth pass over the README and the site (G5)
  follows the tag.

## Not in this release

- **Release manifest, lock-file SBOMs and digest pinning.** The three images were built, pushed and
  attested, but the release workflow's `manifest` job failed on a command-line flag
  (`cyclonedx-py requirements -i <lock>`: `-i` is `--index-url` in cyclonedx-bom 7.x). So v1.17.0 has
  no `release-manifest.json` and no Python lock-file SBOMs, and the Kubernetes manifests are not
  digest-pinned to it. Fixed in #211; all three ship with v1.17.1 (owner decision, 2026-10-16).
- **B7 and B8 real-data results**: v1.17.1, as the IEX overlap days are ingested.
- **C++ ports not done** (documented in PLATFORM_CONVENTIONS §11): the B2-regime
  arm of dark eligibility, the B10 proxy sampler and fit, the exchange-local
  hazard clock.

Full list: `CHANGELOG.md`, section v1.17.0.
