## What this release is, and is not

**It is** a measurement instrument and a set of recorded negative results: research authorisation
(signed pre-declarations that bind script, commit, data and thresholds; a fail-closed holdout
registry; one real-data ledger family), execution benchmark v2 metrics, a venue-aware child
simulator with an invariant suite, a known-null calibration of the inference step, a replay
harness, and paper-path monitoring, risk and resilience code.

**It is not** a trading result. **No signal is promoted. No edge is claimed.** No alpha-track
experiment produced a candidate; the only definitive outcomes are rejections and "underpowered".
Promotion needs an untouched confirmation sample, which this programme does not have. There is
**no latency edge**, the signals are execution inputs and not strategies, and **the fill model is
validated at Level 1 only (deterministic replay), not at Level 2** (REL-05, gate F8): no real
orders or fills exist (decision D4(a)), so nothing here validates the live fill model
empirically. A release that promotes no signal is a success only if the measurement process is
trustworthy and the rejections are recorded (programme 9.1); whether the process is trustworthy is
decided by the open gates below, not by this note.

## Appendix: lessons from the v1.18 run (summary of `IAP_v118_Lessons_2026-10-20.md`)

- Machine time lost (about 5-6 h): two queued studies sat unlaunched about 3-4 h because nobody
  confirmed a start line; a re-download plan read spent sessions the holdout guard correctly
  refused (about 1.7 h) because the guard was not dry-run before approval; a full-suite run on a
  loaded machine failed a load-sensitive test (about 1 h of re-runs).
- Elapsed time lost to process: a squash merge made a signed commit a non-ancestor of main (about
  3 h; signed PRs are now merged with `--merge`); merge cascades from "behind" PRs (2-3 h); a stale
  test list after re-signing (about 1 h); multi-line pastes of sign commands run out of order
  (1-2 h); classifier blocks on signing, deletes and scheduling.
- Audit mistakes that cost a reviewer round: protocol text said 49 centring groups while the frozen
  config said 63; a claim that the signature covered the calibration hash without reading the bind
  tool; a cover note naming a different candidate commit than the identity note; a test report
  mixing two environments.
- What worked: batching green PRs into one merge, `--merge` for signed work, refusal tests for
  guards, honest limits stated in every cover note.
- A five-point checklist before each heavy job (holdout state and signed prereg, commit ancestry,
  disk and RAM, who launches and which log line proves it, failure handling) is adopted for v1.19.
