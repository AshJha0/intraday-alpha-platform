intraday-alpha-platform

An institutional-style, event-driven research-to-production trading platform for equities and FX — deliberately polyglot: Python for research and reference implementations, C++ for the latency-critical path, Rust for safety-critical infrastructure, Java for the strategy/platform layer. Market data → order books → 205-feature factory → 24 alphas → validation → ML → portfolio → fail-closed risk → execution/SOR → deterministic replay → TCA → decision trace → 7-state promotion lifecycle, held together by cross-language golden tests, and run end to end by one command (python -m iap.mvp run) whose golden result is honestly cost-negative. Since v1.9–v1.10 it also has the maker side (a simulator calibrated from the event stream, a posting backtest and a skewed two-sided quoter), auction-imbalance research, optimal-execution schedules, and pre-registration that is costed, code-bound, git-anchored and Ed25519-signed. Since v1.11 an optional LLM research agent works only through that governance, fitted models live in a content-hashed registry with drift monitoring and shadow mode, the Rust feature engine is callable from Python, and most duplicated language copies are frozen by policy. Seven real Nasdaq ITCH sessions and a two-day 2026 holdout have been studied; nothing is claimed to be profitable.

Research truth over backtest cosmetics. The adversarial review of this platform found — and fixed — a generator artifact that left the consolidated equity book crossed 95% of the time and silently inflated ML information coefficients. After the fix (a shared efficient price per instrument) the crossed fraction is 0.26% on the current dataset, every golden file and research report was regenerated, and the alpha promotion count honestly fell from 2 to 0. The full story is a worked case study in LEARN.md §7.
v1.3.0 (2026-10-03): the safety code was wrong in ways its tests could not see. A review found the hard risk engine trusting a reference price stamped in the future, letting NaN through its limit checks, overflowing 64-bit arithmetic differently in each of its three languages, and letting router-bound orders past a venue kill. The execution simulator re-filled a resting order against the same displayed shares on every event. The paper platform could resume a cursor beside a risk snapshot from another moment. All three engines agreed byte for byte throughout — parity proves agreement, not correctness. Each is fixed, pinned by a regression test, and written up as a case study in LEARN.md §21–§25; the changelog lists what is still open.
v1.4.0 (2026-10-03): the dataset was wrong, and every number that came from it was regenerated. Up to v1.3.0 the seeded generator stopped each equity stream's continuous flow 37.6–43.2% of the way through the session, so the equity research had only seen the first part of each day. The flow calibration is fixed (flow now reaches the close; the old dataset is still reproducible byte for byte with equities.flow.calibration = "legacy_budget") and the reports, the ledger, the lifecycle registry and four goldens were regenerated in one CI job. The equity statistics are weaker on the corrected data: one alpha fell from ITERATE to REJECT, EQ03's uncrossed IC went from 0.0298 (t 10.57) to 0.0190 (t 5.78), and the power study detects less than it did. The ML gate now passes and the tree models and the MLP were fitted; none earns its costs. The MVP session trades more and loses more. The looks spent on the old dataset stay in the multiple-testing ledger. Still 0 PROMOTE; details in the changelog.
v1.5.0 (2026-10-04): the corrected research methods are the defaults. v1.3.0 added eleven corrected methods as opt-ins and v1.4.0 kept them opt-in, so every committed research number was still computed under rules the repository itself described as deficient. They are now what runs when nothing is named, and each old rule stays selectable under a legacy name (--methods legacy_v1 reproduces the v1.4.0 report). Same dataset, new rules: the gate t is the HAC t of the pooled slope and the PROMOTE threshold is the ledger's multiple-testing threshold (4.365 instead of 3.0), so three alphas are significant where six were; the cost-aware backtest shows 18 of the 24 alphas never forecasting a move larger than their round-trip cost, so they make no trade, and the six that trade lose 22 to 733 USD where the old sign policy lost five or six figures; verdicts are 0 PROMOTE / 11 ITERATE / 13 REJECT (FX03 down, FX10 and FX11 up); EQ11's gate IC falls from 0.0261 to 0.0038 once blackout rows are scored. The MVP's events, fills and P&L are identical. Nothing was tuned to recover a v1.4.0 conclusion. Still 0 PROMOTE; details in the changelog.
v1.6.0–v1.8.0 (2026-10-04 … 10-10): real data, then an honest out-of-time test. v1.6.0 ran the 24-alpha batch on seven real Nasdaq ITCH sessions: 0 PROMOTE / 8 ITERATE / 4 REJECT, and no trade survived costs. v1.7.0 added the agent layer (a governed broker, pre-registration, a reserve) and combined the equity signals: higher IC (up to t 25), still cost-negative. v1.7.2 measured detection power on real-noise nulls (0 of 20 false flags). v1.8.0 cut a full-day ingest from 260 min / 17.6 GB to 59 min / 7.75 GB with byte-identical output, and ran the first out-of-time holdout: four signals pre-registered and git-timestamped before the 2026 data was touched, all four confirmed. The signals are real; at a one-second horizon they are too small to pay a taker's spread and fees. Those 2026 days are now spent.
v1.9.0 (2026-10-10): harden the evidence, then build the maker side. Two of the seven in-sample days were FOMC days, QQQ was half the rows, and every t-statistic ignored day-level clustering. A new opt-in v3 method bundle samples days by seed and stratum and reports with and without event days, clusters inference by day (and bootstraps whole days), cuts folds at session starts, gates on the equal-weight per-instrument IC, labels ITCH-only results honestly as one Nasdaq book, and bounds label freshness causally. The feature build runs one day per process (--workers N, byte-identical, 5.1x on 5 synthetic days). And because a taker cannot pay ~0.7 bp for a ~0.07 bp edge, the platform now has the maker side: a simulator calibrated from the event stream, a backtest that posts at the touch, fills by queue position, earns the rebate and is charged its measured markout, with an optional passive exit. On synthetic data it still loses (−6.7 bp per trip with the passive exit, −11.4 bp crossing out); the real-session maker run comes next. Every default and published number is unchanged.
v1.10.0: test the maker side properly, and make the research record hard to rewrite. A quoter that keeps a bid and an ask resting through the queue simulator, centred on a reservation price the alpha shifts, with a hard inventory limit and a flatten before the close. On the synthetic golden vector the toy score does not help (+86.50 USD skewed against +120.20 USD unskewed); with a synthetic look-ahead signal the skew earns more over eight days (+3,326.66 vs +2,535.66 USD) at a slightly lower Sharpe per day (34.75 vs 36.95). A look-ahead signal tests the plumbing; it is not evidence about any alpha. Also new, all opt-in and Python-only: the Nasdaq auction-imbalance stream with a closing-cross strategy, Almgren–Chriss schedules, alpha-driven urgency and a forecast VWAP curve. Pre-registrations now cost a look and commit to a fingerprint of the code; the blackboard is anchored to git history; agent writes carry Ed25519 signatures that anyone can re-verify with public keys. A pre-registered, in-sample maker study on the seven real sessions is running; there is no result yet, and an in-sample positive could only justify an out-of-sample test.
v1.11.0: scale and AI, under the governance that came first. The Rust feature engine is now callable from Python (one abi3 wheel built with maturin; about 150x on the 45 native slots in CI, not a pipeline speed-up). Comparing it with the Python reference on every row, not just the golden checkpoints, found a real bug: inside a SNAPSHOT recovery burst the Rust engine read a half-built book. Every golden test had passed, because no checkpoint sits in a burst; the bug is fixed in this release. A polyglot policy freezes 20 duplicated copies so they can no longer grow on their own; nothing was deleted. Fitted models get a content-hashed, immutable registry tied to a pre-registration, with drift and calibration monitoring and a shadow mode that cannot act. And an LLM research agent can now propose, pre-register, run and report, but only through the signed broker: it never sees the signing key, code computes every number, and a finding is refused if it quotes a number its cited artefacts do not contain. Its four behaviour evals pass mocked (where a scripted model attacks the controls) and live (where the model behaved well, so the controls were not stressed). Real-data maker, auction and quoting studies are running, pre-registered and in-sample; no result is reported yet. Deferred: QQQ vs constituents, futures lead-lag, deep order-book baselines.

AI, LLMs and agents: the boundary

The rule was pinned first: LLM reasoning is never on the trading path, is read-only, and cannot override risk or send an order. The governance an agent has to pass through came next (v1.7–v1.10): a write broker over a hash-chained blackboard, costed and code-bound pre-registration, a hidden-seed reserve, signed human approvals, a read-only MCP server, git anchoring and Ed25519 agent signatures. Since v1.11 one optional component calls a model, the research agent, and only when an operator runs it with a key; no test or CI job does. The page says what would be theatre on this data. What's inside

LLM research agent

A Claude model with eight research tools and nothing else: propose, pre-register (signed by a key the model never sees, one look each, capped per session), run a gated study on an allowed dataset, read a report, file a finding. Code computes every metric and the verdict; a finding is filed only if every number in it appears in a cited artefact. Budgets cap spend, tokens, tool calls and pre-registrations; the transcript is kept. Optional [llm] extra; mocked evals in CI (GOVERNANCE §2b).

Model registry & shadow mode

Fitted models as citable records: the id is a content hash of the artefact, data version and dates, features, code fingerprint and seed; records are immutable and re-verified on load; registration needs a pre-registration or is marked exploratory. Feature, prediction and calibration drift (PSI, KS, ECE, Brier, IC decay) as OK/ALERT, and a candidate scored beside the champion that never acts (API_ADAPTIVE §9).

Polyglot policy

Every component that exists in more than one language has one decision per copy: canonical (new behaviour lands here) or frozen (built, tested, golden-pinned, no new features). 18 canonical, 20 frozen, nothing deleted. A CI gate fails a pull request that changes a frozen copy without a POLYGLOT-OVERRIDE: line, and one that adds an API without new-api (POLYGLOT).

Market data foundation

Seeded synthetic equity MBO + multi-venue FX quote generator (regime-switching efficient price, clustered flow, halts/auctions, injected anomalies), raw→normalized pipeline with sequence-gap/duplicate/out-of-order QC, JSONL + IAP1 binary codecs byte-identical across languages, Parquet research datasets.

Order books

L1/L2/MBO reconstruction with FIFO queues, pinned modify semantics, marketable crossing ADDs, snapshot recovery (incl. broken-burst rule), per-venue + consolidated views, deterministic checkpoints — identical state in Python, C++, Rust and Java after every event.

Feature factory

205 registered features across price, microstructure, order flow (OFI L1–L10), liquidity, volatility, time-of-day, cross-asset, venue, regime and execution families; event-driven incremental engines in all four languages validated to 1e-9 against golden checkpoints. Since v1.11 the Rust engine is callable from Python (pyo3, one abi3 wheel, opt-in --engine rust) for the 45 native slots; its row-by-row comparison with Python found and fixed a snapshot-burst bug the checkpoints could not see.

Alpha library

12 equity + 12 FX flagship alphas (microprice, multi-level OFI, queue depletion, momentum/reversal, VWAP deviation, lead-lag, carry-style currency factors, regime-conditioned variants), each with a mandatory economic-rationale docstring and declared feature dependencies.

Validation framework

Event-time labels at 11 horizons (10ms–15m), walk-forward with purging + embargo, automatic leakage tests incl. a recompute-from-raw-events probe, IC/RankIC/pooled-slope HAC t/hit/decay/turnover/edge-breakeven capacity, a persistent multiple-testing ledger, and cost/latency/regime stress — the §20 promotion gates, enforced literally. The opt-in v3 bundle (v1.9) adds day-aligned folds, day-clustered and day-block-bootstrap t, an FOMC/holiday-excluded block and the equal-weight per-instrument gate IC.

ML & meta-labeling

Linear baselines gate the advanced models, literally: trees and the MLP run only if the best linear model shows OOS signal against the frictionless label. On the bundled data it does, barely (ridge, pooled OOS IC +0.0081), so xgboost, lightgbm and the MLP were fitted — and no model earns its costs. A calibrated trade/no-trade meta-label gate, evaluated economically, takes zero trades and is reported as degenerate rather than as a success. Reproducibility manifests (data/feature/model versions, windows, hardware) on every fit.

Portfolio construction

alpha'w − λ·w'Σw − tc(Δw) under position/gross/net/participation/turnover/ vol-target and FX currency-exposure constraints; deterministic projected-gradient production optimizer (Java) matching the Python reference to 1e-9, with a constraint-audit report.

Fail-closed risk

Fat-finger, price-band, stale-price, position/notional/gross/net, loss limits, rate throttle, duplicate-order and self-match prevention, sequence-gap gating, venue-disconnect handling and four-scope kill switches — Rust reference with Java and Python ports, byte-identical audit logs, replayable. Since v1.3.0 also closed against future-stamped marks, NaN, integer overflow and router-bound orders under a venue kill, with an edge golden all three engines replay.

Execution & SOR

Market/limit/IOC/FOK, VWAP/TWAP/POV/IS parent algos, deterministic queue-position modeling for passive orders (pinned depletion rules), fees/rebates/impact, venue latency with seeded jitter, and fee-aware smart order routing — C++ reference fills reproduced exactly by Java and Python. The simulator never fills more than the market displayed or traded. Opt-in since v1.10 (Python only): an Almgren–Chriss IS trajectory and efficient frontier, alpha-driven urgency, and a VWAP on a forecast volume curve.

Maker economics & quoting

A versioned calibration estimated from the event stream (fill rates, queue-depletion hazards, latency, maker markouts, impact) feeds the simulator. A maker backtest posts at the touch behind a gate on expected edge versus measured adverse selection, with a taker or passive exit; a two-sided quoter skews an Avellaneda–Stoikov reservation price with the alpha. Both decompose P&L exactly. Python research code, opt-in; results so far are synthetic (API_TRADING §2.6–2.8).

Auction imbalance

Nasdaq NOII and cross messages decoded in a separate opt-in pass, so the normalized dataset and its version do not change. Auction features (imbalance ratio, reference-price drift, far/near spread, time to cross), cross targets, and a closing-cross strategy with a purged, day-aligned walk-forward. The CLI refuses to backtest without a pre-registration. Since v1.11 it is running on the real sessions, pre-registered and in-sample, with a declared 2026 holdout; no result yet.

Research governance

Every agent write goes through one broker onto a hash-chained blackboard. A pre-registration debits a look on the multiple-testing ledger and records a fingerprint of the alpha's code, features and pinned dependencies; the gate refuses a run if any changed. verify-board checks the chain, that each committed version is a prefix of the current one, the git anchors, and every Ed25519 signature (GOVERNANCE).

Event-driven backtester

Replays every market event in event-time through book → features → alphas → portfolio → risk → execution with modeled decision/wire/venue latency, partial fills and queue position; identity-tested P&L accounting; checkpoint/restart bit-identical to uninterrupted runs.

TCA & attribution

Arrival/VWAP/TWAP benchmarks, Perold implementation-shortfall decomposition (delay/trading/opportunity — exact identity), spread/impact/timing split, post-fill adverse-selection markouts at 100ms/1s/10s, and impact regression versus participation.

Adaptive lifecycle

Models decay, so the platform measures it: pinned PSI/KS drift monitors against serialized research baselines, rolling realized-vs-research IC, drift-triggered refits on purged/embargoed windows, and an IC-gated ACTIVE→WATCH→RETIRED state machine with hysteresis and a CUSUM retirement rule (the legacy consecutive-breach rule stays selectable). In the adaptive backtest RETIRED verifiably halts the allocation; in the live paper loop the gauge is deliberately observational — the AlphaLifecycleRetired alert pages a human, nothing reduces the position automatically (API_ADAPTIVE §6, PLATFORM_CONVENTIONS §12.6). Live PSI, rolling-IC and lifecycle gauges are scraped in paper trading.

Cross-language golden parity

The Python reference generates validated golden vectors (events, book states, codec SHA-256, features, alphas, risk decisions, fills, portfolio); C++, Rust and Java must reproduce every one. tests/harness/run_all.sh prints the parity table in one command. Agreement is not correctness: four engines can agree on a wrong rule, and engines that agree at every checkpoint can differ between them.

Contracts & the Python reference ports

17 JSON Schemas mirrored by 22 frozen, validated Python contracts and 18 runtime-checkable Protocols; canonical JSON reproduced byte for byte in four languages. Python ports of the hard risk engine and the execution stack proven by the same goldens the Java ports use (API_CONTRACTS, API_TRADING).

Promotion lifecycle

RESEARCH → CANDIDATE → VALIDATING → PAPER → ACTIVE ⇄ WATCH → RETIRED: 17 pinned edges, 20 gates reading typed evidence, a byte-deterministic registry and transition log, ports in Java and Rust from one golden. Bootstrapped on the bundled research: 24 CANDIDATE, 0 beyond.

Decision trace & data model

One validated record per decision — signal, portfolio, risk, orders, routing, fills, TCA, attribution — as canonical JSONL with a stream digest that an incident replay must reproduce, indexed by a SQLite/PostgreSQL-portable store (24 tables, 3 views) and rendered by explain() identically in Python, Java, Rust and C++.

The executable MVP

python -m iap.mvp run: seeded feed → books → features → EQ01/EQ03/EQ06 → portfolio → hard risk → TWAP/POV/IS → SOR over three venues → simulator → TCA → trace → SQLite → report, deterministic twice over. The golden run loses 81.53 USD, the realized-IC gap is attributed to the data rather than a leak, and the document says so.

Observability & deployment

Prometheus metrics (rust telemetry + 19 live Java metrics with /metrics, /health), recording + alert rules, two Grafana dashboards, structured JSONL logs, Dockerfiles + docker-compose + Kubernetes manifests, runbooks, governance and reproducibility docs, and a paper-trading mode. Alertmanager routes the alerts; delivery needs an operator-supplied webhook. NetworkPolicies default-deny ingress and egress.

Research papers

Six case studies written from the platform's own measured outputs: OFI predictability, microprice/queue dynamics in FX, cross-venue lead-lag, alpha decay vs latency economics, queue-aware execution and adverse selection, and C++ vs Rust vs Java for event-driven trading.

Performance engineering

Benchmark suite with published methodology (hardware, toolchain, boundaries, variance caveats — no isolated numbers): codec, book, replay, feature engine, alpha scoring and execution-sim stages, plus demo-scale Rust/Java replay throughput.

Quick start

git clone https://github.com/AshJha0/intraday-alpha-platform && cd intraday-alpha-platform

# generate the deterministic synthetic dataset, then the feature/label store
cd python && PYTHONPATH=src python3 -m iap.marketdata && PYTHONPATH=src python3 -m iap.features && cd ..

# run everything — builds and tests all four languages, prints the parity table
bash tests/harness/run_all.sh

# the whole trading loop on one instrument, fully traced; then replay it from its capture
cd python && PYTHONPATH=src python3 -m iap.mvp run && PYTHONPATH=src python3 -m iap.mvp replay --run ../data/mvp/58a10f2194a3c81c && cd ..

# research pipelines (honest reports in research/)
PYTHONPATH=python/src python3 research/alpha_reports/run_all.py
PYTHONPATH=python/src python3 research/ml_reports/run_ml.py

# paper trading with live /metrics on :8080
cd java && bash paper.sh
